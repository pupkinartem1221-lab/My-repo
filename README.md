# CRM-бот для пассажирских перевозок

Telegram-бот для учёта клиентов, реквизитов для оплаты, квитанций и заработка.
Работает на GitHub Actions, сам перезапускается каждые 5 ч 20 мин, данные сохраняются
между перезапусками (в зашифрованном виде в ветке `bot-data`).

## Роли

| Роль | Кто добавляет | Возможности |
|---|---|---|
| 👑 Главный админ | задаётся `OWNER_ID` | всё + добавление/удаление админов |
| 🛡 Админ | главный админ (по @username) | все клиенты и квитанции, реквизиты, подтверждение оплат, проценты, сотрудники, отчёты, журнал |
| 👷 Сотрудник | любой админ (по @username) | свои клиенты (добавить, статус, комментарий, реквизит), загрузка квитанций, своя статистика |

Всем остальным бот **не отвечает**.

**Как подключается новый человек.** Админ вводит его @username. Человек открывает бота и нажимает `/start`.
Админам приходит запрос с его именем и **Telegram ID** — убедитесь, что это тот человек, и нажмите
«✅ Подтвердить» (админов подтверждает только главный админ). Так никто не получит доступ, просто заняв
чужой username. Приглашение действует 14 дней. После подтверждения человек указывает свой ник в CRM.

## Как считается заработок

* Оплата засчитывается только после того, как админ нажмёт **✅ Подтвердить**.
* Сотрудник получает свой процент (по умолчанию **50%**, настраивается для каждого) от суммы оплаты клиента.
  Процент и сумма заработка фиксируются в момент подтверждения — изменение процента не меняет старые оплаты.
* Процент сотрудников меняют админы; процент админов — только главный админ.
* В отчёте админа: оплачено клиентами, доля сотрудников, остаток, разбивка по сотрудникам и реквизитам.
* В **00:00 по Еревану** всем приходит итог дня: админам — общий, сотрудникам — личный.

## Запуск на GitHub Actions

> ⚠️ **Важно.** Правила GitHub не рассчитаны на постоянный хостинг ботов в Actions. GitHub может в любой
> момент отключить workflow или ограничить аккаунт. Для надёжной работы лучше VPS (от ~3–5 $/мес) —
> код переносится без изменений. Периодически сохраняйте себе копию файла `crm.db.enc` из ветки
> `bot-data` вместе с паролем `DB_PASSWORD`.

1. **Репозиторий должен быть публичным** — только так GitHub Actions бесплатен без ограничения минут.
   Код при этом виден всем, а данные — нет: токены хранятся в Secrets, база зашифрована.
2. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
   В настройках бота отключите добавление в группы: *Bot Settings → Allow Groups → Turn off*.
3. Узнайте свой Telegram ID, например у [@userinfobot](https://t.me/userinfobot).
4. Сгенерируйте пароль для шифрования базы (не меньше 24 символов, бот не примет короткий):
   ```bash
   python3 -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   **Сохраните его в надёжном месте: без него данные не восстановить.**
5. В репозитории: **Settings → Secrets and variables → Actions → New repository secret**, добавьте:
   * `BOT_TOKEN` — токен бота;
   * `OWNER_ID` — ваш Telegram ID (только цифры);
   * `DB_PASSWORD` — пароль из шага 4.
6. Код должен быть в ветке `main` — бот запускается только из неё.
7. **Первый запуск:** Actions → CRM Bot → Run workflow → поставьте галочку
   **«Создать новую пустую базу»** → Run. Через ~30 секунд напишите боту `/start`.
   Галочку ставьте **только один раз** — дальше бот перезапускается сам и всегда загружает сохранённую базу.
   Если базы нет, а галочка не стоит, бот не запустится (это защита от случайной потери данных).

### Рекомендуется: хранить данные в отдельном приватном репозитории

По умолчанию зашифрованная база лежит в ветке `bot-data` этого публичного репозитория — скачать файл
может кто угодно, а защищает его только пароль. Надёжнее держать её в **приватном** репозитории:

1. Создайте пустой приватный репозиторий, например `crm-data`.
2. Создайте fine-grained токен (GitHub → Settings → Developer settings → Personal access tokens →
   Fine-grained): доступ только к `crm-data`, права *Contents: Read and write*.
3. В этом репозитории добавьте секрет `DATA_TOKEN` (токен) и переменную
   (*Settings → Secrets and variables → Actions → Variables*) `DATA_REPO` = `ваш-логин/crm-data`.
4. Первый запуск — снова с галочкой «Создать новую пустую базу».

### Обслуживание

* **Остановить бота:** Actions → CRM Bot → `···` → *Disable workflow*, затем отмените **все**
  запущенные и ожидающие запуски CRM Bot.
* **Обновить код:** залейте изменения в `main` — новый код подхватится при следующем плановом
  перезапуске (не позже чем через 5 ч 20 мин). Если нужно сразу — отмените текущий запуск (Cancel run):
  бот сохранит данные и перезапустится (изменения последних секунд перед отменой могут не успеть сохраниться).
* **Сменить пароль базы:** добавьте старый пароль в секрет `DB_PASSWORD_OLD`, новый — в `DB_PASSWORD`.
  После первого сохранения (≈1 минута работы) `DB_PASSWORD_OLD` можно удалить. Старые версии файла,
  зашифрованные старым паролем, на GitHub остаются — поэтому пароль не должен утекать.
* Ветку `bot-data` **не удаляйте и не редактируйте** — в ней хранится база.
* Защитите ветку `main`: *Settings → Rules → Rulesets* → запрет прямых push без pull request.
  Тогда даже при компрометации бота никто не сможет подменить его код.
* Если бот не может сохранить данные несколько минут подряд, главному админу придёт сообщение.

## Локальный запуск (для проверки)

```bash
pip install -r requirements.txt
BOT_TOKEN=... OWNER_ID=... python -m bot
```

Без `DATA_REPO` база хранится только локально в `data/crm.db`.

Зависимости зафиксированы с хешами в `requirements.lock`. Обновление:
`pip-compile --generate-hashes --strip-extras -o requirements.lock requirements.txt`.
